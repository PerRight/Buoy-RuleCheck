# AutoCAD 2027 플러그인 — **Buoy** RuleCheck (BuoyRuleCheck.dll)

엔진(Python)이 판정하고, 이 플러그인은 **도면 스냅샷 추출 → 엔진 호출 → 결과 표시**만 하는 어댑터다.

> **v0.6.0(10-26) Buoy UI + 이름 변경** — "고칠 곳에 떠오르는 부표": 위반 후보 위치에 오브(점으로 된 구)가 떠서 돌고, 고치면 사라진다. 떠 있는 로고(오브)·수정 소요 목록·토스트, 팔레트·리본·명령줄 출력·연결 마법사 5단계·버전 비교·A4 전달 시트를 디자인 번들대로 다시 그렸다. 이름이 **Buoy-RuleCheck**로 바뀌어 명령은 `BRC*`(옛 `GARC*`는 별칭으로 동작), 도면 특성은 `BRC_*`(옛 `GARC_*`도 읽음), 번들은 `BuoyRuleCheck.bundle`. **컴파일 확인만(오류·경고 0)** → 아래 확인표 **36~55**. 화면만 먼저 보려면 `BuoyPreview`(AutoCAD 없이).
> 아래 v0.5 이전 메모는 당시 이름(`GARC*`, `GaRuleCheck`) 그대로 둔다 — 지금은 같은 자리에 `BRC*`, `BuoyRuleCheck`.
> **v0.5.0(10-18) 실도면 연결** — GA_ 레이어가 없는 실제 GA(1/1000 시트, 원점≠AP/기선, 한 시트에 여러 뷰)를 레이어를 바꾸지 않고 검사: `GARCLINK` 마법사(치수표·축척 → 측면도 영역 → AP/FP/기선 → 역할 지정 → 조종위치), `GARCROLE`, `GARCROLESHOW`, 준비 상태 카드, 블록 펼침·호/원/곡선 지원. **컴파일 확인만(오류·경고 0)** → 아래 확인표 **26~35**.
> **v0.4.0(10-18) 기능 3종** — ① 버전 기록·비교 창·생산팀 전달(PDF/PNG) ② 떠 있는 로고 패널(Ctrl+.) ③ 마우스 오버 하이라이트·충족/미충족 툴팁·체크리스트 연동. **AutoCAD 2027 DLL·.NET 10 참조로 컴파일 확인(오류·경고 0, Claude 작업 환경)** — AutoCAD 안 실행은 미확인 → 아래 확인표 **15~25**. 판정 색이 바뀜: **충족 = 파랑**(전에는 초록), 미충족 = 빨강, 확인 필요 = 주황.
> v0.1(2026-10-12) AutoCAD 2027에서 빌드·실행 확인. v0.3 소스는 10-12 16:04 빌드됨(리포트 생성 확인).
> **v0.3.2(10-12 3·4차 수정: layer_counts 전송, 'GA' 접두 레이어 감시 신호, 엔진 주소 허용 목록·리다이렉트 금지 / 10-13 '발표 모드' → '라벨 확대'·명령 `GARCLARGE`)는 빌드 미확인** — `install.ps1`로 다시 빌드할 것.

## 준비물
- AutoCAD 2027 (.NET 10) — LT 버전은 .NET 플러그인 불가
- .NET 10 SDK (`dotnet --list-sdks` → 10.x). 설치: `winget install Microsoft.DotNet.SDK.10`
- (Visual Studio를 쓸 경우 2026 이상 — VS 2022는 .NET 10 대상 빌드 불가)
- AutoCAD 2025/2026(.NET 8)에서 쓰려면 `-p:TargetFramework=net8.0-windows -p:AcadDir=...`로 따로 빌드 (버전 간 바이너리 호환 없음)
- Python 3.10+ (엔진 서버)

## 빌드
```powershell
cd autocad\BuoyRuleCheck
dotnet build -c Release
# AutoCAD 경로가 기본값이 아니면:
dotnet build -c Release -p:AcadDir="D:\Program Files\Autodesk\AutoCAD 2027"
```
결과: `bin\Release\net10.0-windows\BuoyRuleCheck.dll`

## 자동 로드 설치 (권장 — NETLOAD·서버 실행 생략)
AutoCAD를 **모두 닫고** PowerShell에서:
```powershell
cd autocad
powershell -ExecutionPolicy Bypass -File .\install.ps1
```
1. 빌드 → 2. `%APPDATA%\Autodesk\ApplicationPlugins\BuoyRuleCheck.bundle`에 설치(AutoCAD 2027 시작 시 자동 로드) → 3. `BRC_ENGINE_DIR`·`BRC_PYTHON` 사용자 환경변수 설정(`BRC` 입력 시 엔진이 꺼져 있으면 최소화 창으로 자동 실행).
- 코드를 고친 뒤에도 같은 명령으로 다시 설치한다(AutoCAD는 번들 복사본을 쓰므로 `bin` DLL이 잠기지 않는다).
- 처음 한 번 보안 경고가 뜨면 "항상 로드". 매번 뜨면 옵션 → 파일 → 신뢰할 수 있는 위치에 번들 폴더를 추가.
- 제거: `.\uninstall.ps1`

## 수동 실행
1. 엔진 서버 켜기 (별도 터미널):
   ```powershell
   cd engine
   python -m brc serve        # http://127.0.0.1:8765
   ```
   환경변수 `BRC_ENGINE_DIR`에 engine 폴더 경로를 넣어 두면, 연결 실패 시 플러그인이 한 번 자동 실행을 시도한다.
2. AutoCAD에서 `NETLOAD` → `BuoyRuleCheck.dll`
3. 샘플 도면 열기: `samples\S140_rev0_base.dxf` (DXF를 열고 DWG로 저장해도 된다)
4. `BRC` → 오른쪽 팔레트에 결과가 뜬다.

## 화면 (v0.6 — Buoy UI)
원칙: **고칠 곳에 떠오르는 부표** · 도구는 도면을 바꾸지 않는다 · 잉크는 진하기로, 색은 판정에만(문제없음 파랑 · 수정 소요 빨강 · 확인 필요 주황) · "적합"·"승인"이라는 말을 쓰지 않는다 · 빈 입력은 판정하지 않고 '확인 필요'.
- **도면 위 부표**(`BuoyLayer`·`BuoyCard`): 수정 소요·확인 필요 객체의 고칠 자리(엔진 `anchor`)에 30 px 오브. 줌과 관계없이 같은 크기, 28 px 안에 겹치면 숫자로 묶음. 등장 0.7 s(물결 2번) → 5 s에 한 바퀴 자전. 커서를 올리면 ×1.25 + 카드(고칠 내용 · 현재/기준/차이 · 근거), 근거 선(시선·허용선)은 이때만 — 커서를 카드 위로 옮겨도 유지되고, 부표와 카드를 모두 벗어나면 0.15 s 뒤 사라짐. 카드의 `근거 ›`는 팔레트를 펼쳐 그 항목으로. 카드의 ○(핀)를 누르면 그 부표 자리에 고정 — 화면을 옮기거나 확대해도 부표 왼쪽 위를 따라가고, 부표가 도면 창 밖으로 나가면 숨었다가 돌아오면 다시 보임(도면은 그대로). 핀으로 고정, ×로 닫기. 명령 실행 중에는 멈추고 35%로 흐려졌다가 끝나면 1.2 s 다시 검사. 고쳐서 문제없음이 되면 파랑으로 멈추고, 한 번 확인(호버 후 이탈)하면 사라짐. 판정 대상 객체 위에 커서를 올려도 그 객체 부표의 카드가 열린다(AutoCAD 기본 툴팁은 쓰지 않음). 객체를 지워 해결되면 파랑 '문제없음'으로 바뀌어 확인을 기다리고, 저장하면 확인 대기 부표를 한꺼번에 정리. 자전은 급한 순서로 12개까지. 디자인 전달 원문: `docs/design/2026-10-25_오브-부표_개발전달.md`.
- **떠 있는 로고**(`FloatingUi`·`FloatingParts`, 오른쪽 아래): 판 위의 오브 하나가 전체 상태 — 감시 중 흰 등 · 검사 중 빠른 회전(최소 0.6 s) · 수정 소요 빨간 등 + 개수 칩 · 확인 필요 주황 등 + '!' 칩 · 모두 문제없음 파란 등 정지 · 엔진 연결 끊김 45% 흐림·등 꺼짐. 클릭 또는 `Ctrl+.` → 로고 위에 **수정 소요 목록**(한 줄 누르면 그 자리로 이동해 부표 카드 고정, '팔레트에서 자세히'). 해결이 생기면 토스트 "해결 N건 · 저장하면 버전 기록에 남아요". 드래그로 이동, 위치는 `%APPDATA%\BuoyRuleCheck\ui.json`(옛 `GaRuleCheck\ui.json`이 있으면 이어 씀).
- **팔레트**(`ResultPanel`·`PaletteParts`·`RuleCard`): 머리에 워드마크 **Buoy** RuleCheck · 전체 상태 오브 · `rev · 도면 · 시각` · 엔진 상태. 검토 탭의 항목 카드는 띠·칠한 배지 없이 오브 점과 글자로 상태(● 수정 소요 / 확인 필요 / 문제없음), 고칠 내용 제목, 게이지(기준·현재·최악 조건), 기여 객체 줄(올리면 도면 강조, 누르면 이동), [부표로 이동] · 규정 번호 · 재계산/캐시. [수정 소요만] 필터. 아래에 고지 문구 고정: "규칙 엔진의 후보 판정입니다. 선급 승인이 아니며 최종 판단은 설계자 검토로 합니다."
- **리본 'Buoy-RuleCheck' 탭**: 검토 · 입력 · 표시·기록 · 버전 4패널, 자주 안 쓰는 명령(엔진 확인·역할 지정/보기·초기 설정·로고·동작 줄이기)은 패널 아래 펼침에. 아이콘은 잉크 한 색 선 그림(판정 색 없음) — 밝은/어두운 테마(`COLORTHEME`)에 맞춰 다시 칠함. '검사 시작'만 멈춘 오브.
- **명령줄**: 검사마다 `[BRC] rev 2 · 다시 계산 0.3 s — 가시거리` / `[BRC] rev 2 · 수정 소요 1 — 가시거리` / `rev 3 · 문제없음 — 가시거리 기준 충족` / `남은 수정 소요 0` / `확인 필요 1 — … (빈 입력은 판정하지 않음)`.
- **실도면 연결 5단계**(`LinkWizard`·`ParticularsDialog`·`LinkProgress`): 1단계 창 — 도면에서 찾은 값 옆 '● 확인' 또는 [고치기], 빈 값은 주황 고리 '확인 필요', 흘수 조건 줄 편집. [적용하고 다음] · [이 단계 건너뛰기] · [취소]. 2~5단계는 AutoCAD 창 위쪽 가운데 안내 띠(5칸 진행 줄 · 지금 할 일 · 'Enter 건너뛰기 · Esc 멈춤'), 포커스를 가져가지 않음. `BRCROLESHOW`는 역할 색(선체 흰 잉크 · 장애물 연보라 · 충돌격벽 청록 · 조종위치 연두)과 팔레트의 범례 카드.
- **버전 비교**(`CompareForm`·`CompareParts`·`CompareCanvas`): 이전/이후 버전 고르기, 나란히 · 겹쳐 · 차이만(분할 버튼), 겹쳐 보기 투명도 슬라이더, 요약 줄 "수정 소요 3 → 0 · 변경 4건 · 전체 ● 수정 소요 → ● 문제없음 · 확인 필요 0", 변경 카드(번호 · 제목 · 해결/기준 충족 · 수치 변화), 범례. 추가 초록 빗금 ○ · 삭제 빨강 파선 □ · 변경 노랑 ◇.
- **생산팀 전달 A4**(`ExportSheet`): 흰 종이 잉크 — 머리 'GA 변경 전달 · 생산팀' · 도면 번호 v1 → v2 · 날짜·작성자·사유, 차이 그림 + 범례, ①②③④ 변경 목록, 확인란(생산 ____ 일자 ____), 고지 문구, 워드마크 'Buoy RuleCheck · 1 / 1'.
- **오류 기록**: 화면 쪽 이벤트(부표·카드·로고·타이머·도면 탭 바꿈 등)에서 예외가 나면 AutoCAD 오류 창 대신 명령줄에 `[BRC] 내부 오류(어디) — 예외: 메시지` 한 줄, 전체 스택은 `%APPDATA%\BuoyRuleCheck\error.log`. 판정을 받은 뒤 표시가 실패하면 판정은 그대로 두고 `[BRC] … 표시 오류`. 엔진 연결 문제가 아닌 플러그인 오류는 '연결 끊김' 대신 '검사하지 못함'.
- **동작 줄이기**: `BRCMOTION`(리본 펼침) 또는 Windows '애니메이션 표시' 끔 → 오브·부표·로고가 멈춘 자세, 색은 그대로.
- **미리보기**: `autocad\BuoyPreview`에서 `dotnet run` — AutoCAD 없이 팔레트·로고·목록·토스트·마법사·버전 비교·A4를 샘플 응답으로 띄움(같은 소스 파일을 링크).

- **[범위 보기]**: 시선·허용 한계선·대상 객체가 한 화면에 들어오게 자동 줌 (사각 거리가 수백 m라 수동 줌이 번거로운 문제 해결)
- **라벨 확대**(구 '발표 모드'): 도면 위 라벨 글자·선 두께·표식 크기만 2.5배 — 프로젝터·화면 공유에서 잘 보이게. 판정·도면 객체·시스템 변수는 바뀌지 않음 (리본·팔레트·`BRCLARGE`)
- 카드 배경이 검게 칠해질 수 있던 문제 수정(투명 부모 위 Clear)

### v0.4 추가 (10-18)
- **버전 기록**: 도면을 저장하면(또는 `BRCVERSION`) 작성자·수정 사유(규정 위반 / 피드백 / 기타)·관련 규정 조항 또는 피드백 내용·메모를 받아 버전을 남긴다. 저장 위치: 도면 옆 `<도면이름>.brc\`(versions.json + v{n}.raw.json — GA_ 레이어 스냅샷, 도면 내용이므로 PC 밖으로 보내지 않음). GA_ 레이어·선박 정보가 그대로면 묻지 않는다. 저장할 때 자동으로 묻는 것은 그 도면을 **BRC로 감시 중일 때만**이다(감시 전이면 `BRCVERSION`으로 직접 기록). 감시 중이고 마지막 검사 뒤에 바뀐 것이 있으면 기록 직전에 한 번 더 검사해 그 결과를 함께 남긴다(감시 전이면 검사 결과 없이 형상만 기록).
- **버전 비교 창**(`BRCCOMPARE`, 리본 '버전'): 아무 두 버전(기본 직전 → 현재). **나란히 보기**(두 칸이 같이 확대·이동) / **겹쳐 보기**(이후 투명도 슬라이더) / **차이만 강조**(추가 초록 빗금, 삭제 빨강 파선, 변경 노랑 — 이전 점선·이후 실선). 변경마다 번호 표식(추가 ○ · 삭제 □ · 변경 ◇), 표식·목록을 누르면 그 위치로 확대. 오른쪽 **변경 내역**: 변경 전·후 값, 수정 사유, 이번 수정으로 해결된 위반. '해결'은 이후가 충족이거나 객체가 삭제(그리고 규칙을 판정할 수 있을 때)된 경우만이고, 판정 못 함·입력 누락·적용 제외로 바뀐 것은 **⚠ 확인 필요**로 따로(주황) 적는다. 요약 줄에 두 버전의 전체 판정과 확인 필요 개수. [도면에 표시]로 AutoCAD 도면 위에도 임시 표시(그 도면 탭이 활성일 때만). 변경 내용·해결 판단은 엔진(`/v1/compare`) 계산.
- **생산팀 전달**: 비교 창 버튼 → PDF 또는 PNG 한 장(A4 가로) — 도면 번호(`BRC_DWG_NO`, 없으면 파일 이름), vX → vY, 날짜, 작성자, 수정 사유, 차이 강조 그림, 번호 매긴 변경 목록, 범례. 흑백 인쇄에서도 색 + 선 모양 + 표식 모양 + 기호(+ − ~)로 구분.
- **떠 있는 로고**(오른쪽 아래): 클릭 또는 `Ctrl+.` → 검토 패널이 로고 쪽에서 0.25초에 펼쳐짐, 다시 누르면 접히고 로고만 남음(도킹 팔레트도 숨김). 미충족 개수 빨간 배지(미충족이 없고 확인 필요만 있으면 주황 숫자, 엔진 응답 없음·판정 불가면 주황 '!'). 도면 탭을 바꾸면 그 도면 상태로 바뀜. 드래그로 이동, 위치·열림 상태는 `%APPDATA%\BuoyRuleCheck\ui.json`. 스크린리더에 '펼쳐짐/접힘' 상태 제공. (v0.6부터 로고는 코드로 그린 오브, 그림 파일 없음.) `BRCLOGO`로 숨기기.
- **마우스 오버**: 판정 대상 객체에 커서를 올리면 상태 색 굵은 외곽선(닫힌 도형은 반투명 채우기) + 툴팁 "✔ 충족 / ✖ 미충족 / ⚠ 확인 필요 — 규칙, 기준, 실제, 차이, 가이드". 닫힌 도형 안쪽에 올려도 잡힌다(공간 인덱스). 계산은 40 ms에 한 번.
- **점검 항목**: 규칙 카드 안에 객체별 줄(미충족 → 확인 필요 → 충족). 줄에 마우스 → 도면 강조, 클릭 → 그 객체로 확대. 탭 줄 오른쪽 **[미충족만 보기]**(숨긴 확인 필요 개수는 주황으로 남김).
- 전체 판정 문구가 길면 두 줄로 보여 잘리지 않음.

## 설계 메모
- **표시는 Transient(임시 그래픽)만** 쓴다. 도면 DB를 수정하지 않으니 Undo 기록이 오염되지 않고 저장 파일에도 남지 않는다.
- **이벤트는 "다시 검사" 신호로만** 쓴다. 매번 GA_ 레이어 전체를 스냅샷으로 보내고, 무엇이 바뀌었는지는 엔진이 계산한다(→ Undo/Redo/복사/레이어 변경 어느 경로든 동기화가 맞음).
- 엔진 연결 실패·플러그인 예외 → 항상 "검토 불가"로 표시. 충족(파랑)으로 남지 않는다.
- **판정 색**: 문제없음 파랑 · 수정 소요 빨강 · 확인 필요 주황 — 판정에만 쓰고 UI 크롬(버튼·탭·아이콘)은 흑백 잉크 단계로. 버전 비교의 추가 초록 · 삭제 빨강(파선) · 변경 노랑과 섞이지 않게 문제없음에 초록을 쓰지 않는다.
- **문구는 `UiText.cs` 한곳**: 화면·명령줄·토스트·A4의 말은 여기서 만든다. "적합"·"승인"을 쓰지 않는다(고지 문구 안의 "선급 승인이 아니며"만 예외).
- **도면을 바꾸는 것은 사용자가 고른 입력뿐**: 검사·표시·부표·호버·`BRC` 시작은 도면 DB를 건드리지 않는다. 바꾸는 경우는 선박 정보 저장·`BRCPICK`(특성), `BRCEYE`·연결 마법사 5단계(GA_EYE 점과 그 레이어), `BRCROLE`·마법사 4단계(역할 XRecord), `BRCSETUP`(GA_ 레이어·라벨 스타일·특성 틀)뿐. 옛 키(`GARC_*`)·옛 XRecord는 이때 새 이름으로 옮긴다.
- **엔진 버전 확인**: 처음 연결할 때 `/v1/health`의 version을, 그 뒤로는 응답마다 `Server` 헤더(`brc/0.5.0`, 옛 엔진 `garc/0.4.0`)를 본다. 0.5.0보다 낮거나 엔진 표시가 없으면(업그레이드 뒤 옛 `python -m garc serve`가 떠 있는 경우) 판정하지 않고 '엔진 창을 닫고 다시 검사' 안내 — 옛 엔진이 `BRC_*` 특성을 못 읽어 '입력 누락'으로 잘못 보이는 것을 막는다. `install.ps1`도 켜져 있던 엔진을 끈다.
- **부표도 Transient**: 화면 크기 고정은 ViewportDraw에서 뷰의 픽셀 크기를 받아 그린다. 도면 DB·Undo·저장에 남지 않는다.
  그리는 방법(10-26 사용자 PC에서 부표가 안 보여 바꿈): .NET에서 `Drawable`을 직접 상속한 객체는 AutoCAD 쪽 실체가 없어 Transient로 받아들여지지 않았다(예외를 삼켜 조용히 안 그려짐).
  지금은 도면에 넣지 않은 무한선(Xline) 하나를 Transient로 올리고, 그 객체에만 걸리는 `DrawableOverrule`(`BuoyOverrule`, `IsApplicable`이 포인터로 비교)이 무한선 대신 부표를 그린다.
  도면의 다른 XLINE은 그대로 그려진다. 올리기·그리기 실패는 `[BRC] 내부 오류(부표 …)`와 error.log로 남고(그리기 콜백 안에서는 명령줄에 쓰지 않고 다음 박자에서), `BRCHEALTH`가 `부표 n개 · 표시 켜짐 · 그릴 자리 있음 · 오버룰 적용 n회 · 그리기 호출 n회(그림 n회) · 1 px = …`를 보여 준다. 지우지 못한 무한선은 해제하지 않고 숨긴다(해제된 객체를 AutoCAD가 그리지 않게). 종료 때 오버룰을 뗀다. `Overrule.Overruling`은 켠다(꺼져 있으면 오버룰이 동작하지 않음).
- **버전 비교도 판단은 엔진**: 무엇이 바뀌었고(handle 기준) 어떤 위반이 해결·발생했는지는 `/v1/compare`가 계산하고, 비교 창은 그리기·고르기·내보내기만 한다.
- **판단 없는 추출**: 폴리선 호는 bulge 값만 보내고 분할은 엔진이 한다. 블록은 펼쳐서 하위 형상을 보낸다(GA_EYE는 삽입점). 펼칠 수 없거나 배열(MINSERT)·프록시·OLE가 든 블록은 삽입점만 보내고, 엔진이 그 블록을 영역 안팎과 관계없이 '검토 불가'로 멈춘다.
- **엔진 주소는 루프백만**: `BRC_ENGINE_URL`(옛 `GARC_ENGINE_URL`도 읽음)이 127.0.0.1·localhost·::1의 http 주소가 아니면 무시하고 기본값을 쓴다. HttpClient는 시스템 프록시를 쓰지 않는다(`UseProxy = false`).
- **문서 ID**: FingerprintGuid + 열린 문서마다 새 GUID. 같은 원본에서 복사한 도면을 동시에 열어도 엔진 세션이 섞이지 않는다(문서를 다시 열면 이력은 새로 시작).
