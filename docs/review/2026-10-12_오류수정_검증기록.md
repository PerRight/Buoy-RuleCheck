## 4. 남은 한계 (알고 쓰기)
- **범위 안 오타는 못 잡는다**: 조종위치를 선체 안 다른 x로 찍은 경우(18 → 118), 선미 흘수 오타(6.5 → 3.5), 범위 안 기선 오타(0 → 2). 도면 위 표시(조종위치 원·수선)를 사람이 확인한다. 발표에서 "모든 입력 실수를 막는다"고 말하지 않는다.
- **GA_ 예약 이름**: `GA_HULL·GA_EYE·GA_OBST·GA_BULB·GA_BHD_COLL`로 시작하거나 그 앞부분(5자↑)이거나 한 글자만 다른 이름(`GA_FULL`, `GA_BULK` 포함)의 레이어에 객체가 있으면 해당 규칙이 '검토 불가'. 보조선은 `GA_REF`·`GA_DIM`·`GA_TEXT` 같은 이름을 쓴다(4차에서 이름 160여 개 확인 — 팀이 쓸 법한 보조 레이어 이름 중 잘못 막힌 것 없음).
- **기선 대조는 GA_HULL에 용골선이 있어야 동작**: 중앙부 바닥선이 절반 이상 없으면 약해진다. 반대로 기선보다 허용차 넘게 깊은 구조(긴 스케그·큰 레이크드 킬·계단 용골)가 중앙부 절반 넘게 걸치면 정상 도면도 '검토 불가'가 된다(5차 합성 시험에서 확인, 현실형 17,000건에서는 0건) — 기선을 중앙부 용골 높이에 둘 것.
- **'GA' 접두 자체가 깨진 레이어 이름**(`G_OBST`, 키릴·그리스 문자로 쓴 A 등)은 비슷한 이름으로 감지하지 못한다.
- **1950년 이전 용골일**은 적용 제외로 넘길 수 없다(오타로 보고 멈춤). 실제로 그런 배를 다룰 일이 생기면 범위를 조정한다.
- AP·FP와 L(ICLL) 길이의 일치 대조는 없다(FP 정의 확인 후 결정 — 표인범).
- 블록(INSERT) 장애물은 아직 지원하지 않는다('검토 불가'로 멈춤).

## 8. 10-13 '라벨 확대' 이름 변경·GitHub 공개 준비 (Sonnet 6·7차)

| 지적 (6차) | 심각도 | 반영 | 7차 결과 |
|---|---|---|---|
| ps1이 저장소 안에 CRLF로 저장돼 새 clone마다 '수정됨' | 중간 | 저장소 안 LF로 정규화, 체크아웃 시 CRLF·BOM 유지 | 해결 — autocrlf true/false 모두 status 깨끗, 원본과 바이트 동일 |
| CLI 리포트(`ga_report.html`, `-o 리포트.html`) 미차단 | 중간 | 이름 패턴 → (7차 후) **HTML 전부 차단 + 예시 1개 허용** | 해결 — `-o` 임의 이름도 막힘 |
| 커밋 작성자에 개인 이메일 | 중간 | 정리용 git 사본의 작성자를 noreply로 다시 씀. 실제 업로드는 PC 폴더에서 새로 `git init` → 올리는 사람의 GitHub 이메일 비공개 설정 필요 | 해결(도달 가능한 이력 0건) |
| 대문자 확장자(`.DWG`), dwt·dwf, 캐시 폴더 | 낮음 | 확장자 대소문자 무관 패턴, 예외 줄보다 앞에 배치 | 해결 — ignorecase true/false 모두 샘플만 허용 |
| CI ezdxf 버전 미고정 | 낮음 | `ezdxf==1.4.4` | 해결 — 3.10~3.14 모두 69개 통과, skip 0, 표 diff 0 |
| PR 템플릿 검증 범위·'빌드 미확인', README 문구, 확인표 14번 | 낮음 | 반영 | 해결 |
| (7차) 기본 브랜치가 `master`로 만들어지면 첫 push에 CI 안 돎 | 낮음 | 워크플로 `branches: [main, master]` + 올리는 순서에 `main` 명시 | 반영 |

**업로드 시나리오 재현(7차)**: PC 폴더와 같은 내용(빌드 산출물 bin/obj, 옛 리포트 HTML, `__pycache__` 포함)에서 `git init` → `git add -A` → 추적 파일 56개가 정리용 저장소 HEAD와 **트리 해시까지 동일**. autocrlf·ignorecase 9가지 조합 모두 같음. 실도면·리포트·빌드 산출물은 모두 제외.
7차 뒤에 바꾼 두 가지(HTML 전부 차단, CI 브랜치 `master` 허용)는 Opus가 같은 업로드 시나리오로 다시 확인: 추적 파일 56개 동일, 가짜 실도면(`real.DwG`, `a.Dxf`)·리포트(`out.html`, `검토결과.htm`, `x.HTML`)는 ignorecase true/false 모두 차단, CONTRIBUTING 예외 절차(`!samples/…` 맨 끝 추가)는 동작.
**한계**: 실제 GitHub Actions 러너와 액션 버전(`checkout@v5`, `setup-python@v6`)은 이 환경에서 GitHub 접근이 막혀 확인하지 못함 — 첫 push 뒤 Actions 탭에서 초록 확인. C#은 문자열·주석만 바뀜(구문 트리 비교로 확인), 빌드는 여전히 사용자 PC 몫(확인표 1~14).
