# 2026-10-26 Buoy UI + 이름 변경 검증 기록 (엔진 0.5.0 / 플러그인 0.6.0)

대상은 `f590a73..HEAD`이다. `Bouy-RuleCheck_UI_prompt.md`와 디자인 번들(보드 01~08)에 따라 화면을 바꾸고 이름을 Buoy-RuleCheck로 바꾼 작업이다.
- 테마 v2, 오브 렌더러, 도면 위 부표·카드·상태 흐름, 떠 있는 로고·수정 소요 목록·토스트, 팔레트, 리본, 명령줄 문구, 연결 마법사 5단계, 버전 비교, A4 전달 시트
- 엔진 표시용 필드: 요소 `anchor`·`fix`, 비교 변경 항목 제목·수치 변화. 판정에는 쓰지 않는다.
- 이름: 패키지 `brc`(옛 `garc` 별칭), 특성 `BRC_*`(옛 `GARC_*`도 읽음), XRecord `BRC_ROLES`, 명령 `BRC*`(옛 `GARC*` 별칭), 버전 폴더 `.brc`, 환경변수 `BRC_*`, 번들 `BuoyRuleCheck.bundle`

작성은 Opus 5.5, 독립 검증은 Sonnet 5.5(Agent `model: "sonnet"`)가 4차까지 했다. 검증자는 저장소를 고치지 않고 scratchpad의 별도 폴더(`verify_brc1`~`verify_brc4`)에서 클론과 프로브로 재현했다. 1차는 기능 전체를 봤고, 2~4차는 직전 수정만 적대적으로 봤다. 고칠 때마다 새 검증자로 다시 검증했다.

C# 확인은 컴파일과 순수 로직 실행까지만이다.
- 컴파일은 AutoCAD 2027 DLL·.NET 10 WindowsDesktop을 참조해 커밋마다 오류 0·경고 0이었다.
- 순수 로직은 `UiText`·`Dto`·`EngineClient`·`DrawingPropsText`·`OrbModel`·`BuoyAnim`을 net10.0 콘솔에 링크해 실행했다.
- WinForms 화면은 `BuoyPreview`로 그려 디자인 보드와 대조했다.
- **AutoCAD 안 동작은 미확인**이다. `autocad/README.md` 확인표 36~55로 확인해야 한다.

합성 샘플(S140)만 썼다. 이름 변경 전후 판정 대조에 쓴 실도면 1건은 저장소 밖에만 두었다.

공통 결과: 마지막 커밋 기준으로 엔진 테스트 161개가 통과했고, 플러그인·BuoyPreview 빌드는 오류 0·경고 0이다.

## 사용자 PC(Windows, Python 3.14) 테스트 — 수정 `CLI --json`
- 증상: `python -m unittest discover -s tests`에서 `test_cli_old_and_new_and_old_schema` 1건이 오류였다(161개 중). `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xbc`가 났다.
- 원인: 한국어 Windows에서 파이프로 받은 stdout은 cp949다. CLI `--json`이 한글을 cp949로 써서, UTF-8로 읽는 쪽이 깨졌다. 2026-10-13 기록이 '남은 한계'로 적어 둔 문제(cp949 파이프에서 `--json`의 '—' 등이 '?'로 바뀜)와 뿌리가 같다. 리눅스 CI는 UTF-8이라 잡지 못했다.
- 수정: `--json`은 콘솔이면 한글 그대로, 파이프·파일이면 ASCII 이스케이프 JSON으로 쓴다. 어떤 코드 페이지로 읽어도 같은 값이고, 데이터 손실도 없다.
- 회귀 테스트: 이 테스트를 `PYTHONIOENCODING=cp949`로 돌리게 바꿔 리눅스 CI에서도 같은 조건을 만든다. 고치기 전 코드에서는 실패하고, 고친 뒤에는 통과한다.
- 덤: 테스트 두 곳에서 HTTPError 응답을 닫지 않아 Python 3.14가 ResourceWarning을 냈다. 응답을 닫게 고쳤다.

## 일부러 고치지 않은 것
- 버전 비교 '삭제' 빨강 파선과 1단계 '확인' 파란 점: 디자인 보드 지정이다. 검증자 의견도 '수용'이었고, 범례를 늘 보이게 두기를 권했다.
- `.brc`·`.garc` 폴더가 둘 다 있으면 `.brc`만 쓴다(병합 안 함). 옛 플러그인과 섞어 쓸 때만 생기며 지워지는 것은 없다. 이후 병합을 검토한다.
- CLI `--prop BRC_*`를 옛 이름 도면에 주면 PROP_DUPLICATE가 난다. 도구 사용 한정이다.
- `BRC_X_FP=1e308`에서 OverflowError(서버 500)가 난다. 이름 변경 전부터 있었고, 판정은 하지 않는다(500). 엔진 규칙 쪽에서 따로 고친다.
- 사용자 문구에 남은 '위반': 버전 사유 '규정 위반'(사용자가 고르는 분류)과 리포트의 '입력 계약 위반'이다. 금지어가 아니고, 문구 정리 때 함께 본다.
