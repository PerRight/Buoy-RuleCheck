# 1차 멘토링 준비 피드백 정리 (2026-10-12 수신)

> 대상: 홍대도면반 계획서(가시거리 1건 + 선수격벽 1건, AutoCAD 플러그인)
> 정리: 손종민 · 상태 표기 ✅ 완료 / 🟡 초안(검증 필요) / ⬜ 미착수

## 1. 핵심 메시지
> **AutoCAD 플러그인보다 먼저 독립 규칙 엔진과 24건 기대값 테스트를 고정할 것.**
> 플러그인은 결과를 보여주는 어댑터로 두면, 좌표·단위·누락 입력·Undo 상황에서 신뢰성을 설명하기 쉽다.

해석: 심사·멘토가 볼 질문은 "플러그인이 화면에 뭘 띄우나"가 아니라 **"그 판정이 맞다는 걸 어떻게 아나"**다. 정답이 정해진 케이스로 엔진을 먼저 증명하고, CAD 쪽은 그 엔진에 입력을 넣고 결과를 그리는 얇은 층으로 둔다.

→ 우리 결정: 구조를 `engine/`(Python, 판정 전담) + `autocad/`(C# 어댑터)로 나누고, 엔진은 AutoCAD 없이 테스트한다. 같은 raw JSON 계약을 DXF 경로도 쓰므로 AutoCAD 없이도 전 흐름을 재현한다.

### 2-1. 피드백으로 고친 실제 버그
기존(FreeCAD 버전) 엔진은 "판정된 규칙이 하나라도 있으면 나머지 입력 누락을 무시하고 PASS"였다. 규칙이 2개뿐이면 가시거리 입력이 빠져도 화면이 초록이 된다. → 새 엔진은 `incomplete`로 표시하고 테스트(`test_partial_pass_is_not_green`)로 고정했다.

## 4. "가장 막힌 질문 3개" 초안 (팀 확정 필요)
1. **흘수 조건의 범위**: V/22는 "모든 흘수·트림·갑판화물 조건"인데, 기본설계 GA 단계에서 검토할 대표 조건을 무엇으로 잡는 게 실무적인가? (만재 출항 + 밸러스트 도착이면 충분한가, 적재지침서 조건을 다 넣어야 하나)
2. **조종위치·눈높이**: 실무에서 conning position을 GA의 어느 점으로 보나(선교 중앙 콘솔? 중심선?), 눈높이 1.8 m를 선교 갑판 기준으로 두는 게 맞나?
3. **측면도만으로 충분한가**: 좌우 10°·사각 섹터 각도는 평면도가 필요하다. 해커톤 범위에서 측면도 중심선 검토 + "평면 미검토" 명시로 가도 되는지, 아니면 평면 1개 규칙을 추가해야 설득력이 있는지.

(예비) 충돌격벽 L로 ICLL 길이를 도면에서 어떻게 받는 게 자연스러운가 — 설계자가 직접 입력 vs 형심·수선에서 계산.

## 5. 발표 화면에 남길 경계 문구
- 팔레트 상단 고정: "규칙 엔진의 후보 판정입니다. 선급 승인이나 적합 증명이 아니며, 최종 판단은 설계자·선급 검토로 합니다."
- 초록 상태 문구: "규칙 후보 기준 충족 — 최종 판단은 설계자 검토" ("적합", "승인", "통과 확정" 단어 쓰지 않음)
- 각 결과 상세에 "이 판정이 다루지 않는 것" 목록 표시(평면 10°, 사각 섹터, 수밀 높이 …)
- 발표 슬라이드: 판정 = 결정론적 규칙 엔진, AI = 설명만. 사람 = 최종 검토. 세 역할을 한 장에.
