# 생성형 AI 설명 — 빈칸 방식 (2026-10-30 결정)

> 엔진 0.6.0 · 플러그인 0.7.0. 코드: `engine/brc/explain.py`(재료·검사·채우기), `engine/brc/ai.py`(외부 호출 한 곳),
> `autocad/BuoyRuleCheck/AiExplain.cs`(설명 창·변경 설명 창·BRCAI). 테스트 `engine/tests/test_explain.py`.

## 1. 결정

| 항목 | 정한 것 |
|---|---|
| 방식 | **A — 외부 LLM(Claude API)에 숫자 대신 빈칸만 보낸다.** (B 로컬 LLM은 시연 PC 설치·속도·한국어 품질 위험, C 템플릿만은 AX 해커톤에서 AI 요소가 없음) |
| 범위 | 항목 카드 **[설명]**(판정 설명) + 생산팀 전달 A4의 **변경 설명** 초안 |
| 기본값 | **꺼짐.** `BRCAI`에서 켜고 API 키를 넣어야 보낸다. 꺼져 있거나 키·인터넷이 없으면 기본 설명(템플릿) |
| 원칙 예외 | "도면 내용을 외부 서비스로 보내지 않는다"는 그대로 — 이 기능은 도면 내용이 아닌 **정해진 어휘와 빈칸 이름**만 보낸다. 외부로 나가는 코드는 `ai.py` 하나 |
| 누가 | 사용자(팀) 결정 10-30, 구현 Claude(Opus), 검증 Sonnet |

## 2. 무엇을 보내고 무엇을 안 보내나

| 보낸다 (정해진 어휘) | 보내지 않는다 |
|---|---|
| 규칙 ID·이름·조항(`SOLAS Ch.V Reg.22.1.1` 등) | 도면 좌표·치수·LOA·L·흘수 값 — **숫자 전부** |
| 판정 상태(`fail`/`pass`/`na`/`review`/`skip`)와 한국어 이름 | 흘수 조건 이름(예: '밸러스트 도착') |
| 판정 분류(`blind_distance_exceeds`·`below_lower` 등)와 뜻 | 객체 번호(handle)·레이어·블록 이름 |
| 원인 객체의 **역할 종류**(장애물·선체 윤곽 …) | 도면·파일·선명·버전 이름 |
| 고칠 방향(“선미 쪽으로 {고칠양} 이상 옮기기”) | 엔진 판정 문장·제안 문장 원문(숫자 포함 → 빈칸 `{엔진결과}`·`{엔진제안}`으로만) |
| 규칙이 다루지 않는 범위(숫자 없이 쓴 문장) | API 키(헤더로만, 본문·미리보기에 없음) |
| 빈칸 **이름과 뜻**(`{사각거리}`: 선수 앞 수면이 가려지는 거리) | — |
| 변경 설명: 바뀐 항목 **종류**(장애물 추가·충돌격벽 수정 …), 해결/새 수정 소요/확인 필요 **규칙 이름**, 수정 소요가 줄었는지(줄어듦/늘어남/같음) | 변경 건수·위반 건수(빈칸으로) |

[보낸 내용](설명 창) · [보낼 내용 미리보기](BRCAI)가 실제 본문 전체를 그대로 보여 준다(CLI: `python -m brc explain <도면> --mode preview`).

## 3. 흐름

```
엔진 판정(RuleResult) ─ explain.rule_brief ─┬─ 빈칸 값 slots: {사각거리}=433.84 m, {최악조건}='밸러스트 도착' …  (PC 안)
버전 비교(/v1/compare) ─ explain.change_brief ┤
                                             ├─ 보낼 사실 public + 빈칸 뜻 slot_help  ──(mode=ai, 키 있음)──▶ ai.call ─▶ Claude API
                                             └─ 기본 설명 template ─ fill ─▶ 바로 표시                                  │
                                                                                                                 ▼
                              표시 ◀─ fill(AI 문장의 {빈칸} → 엔진 값) ◀─ check_ai_text 통과 ◀── AI 문장(빈칸 이름만, 숫자 없음)
                                         └ 통과 못 하면 버리고 기본 설명 + 이유(fallback_ko)
```

- 숫자는 **언제나 엔진 값**이다. AI가 숫자를 쓰면 그 답 전체를 버린다(조항 번호 문자열만 예외).
- 제안 높이는 엔진 제안 문구와 같은 내림 값(`evidence.suggestion_z`), 격벽 이동량은 요소 판정 `fix.delta`(올림)를 그대로 쓴다.

## 4. AI 답 검사 (`check_ai_text`) — 하나라도 걸리면 기본 설명

1. 길이 15~700자
2. 모르는 빈칸(`{선명}` 등) — 보낸 빈칸 이름만
3. 조항 번호 문자열을 지운 뒤 숫자(아라비아·전각·동그라미 숫자 포함)
4. 깨진 빈칸 표기, 숫자를 글로 쓴 단위(미터·센티…), 링크·코드 블록
5. 쓰면 안 되는 말: 적합·승인·합격·인증·보증·통과 확정
6. 판정과 반대되는 말(규칙 설명만): 수정 소요인데 '문제없', 문제없음인데 '수정 소요', 판정 안 함인데 둘 중 하나

## 5. 외부 호출 (`ai.py`)

- 주소 고정 `https://api.anthropic.com/v1/messages`, 리다이렉트 거부, `anthropic-version: 2026-10-21`(10-30 문서 확인 — 이 버전부터 temperature 등은 보내지 않음).
- 모델 기본 `claude-haiku-5-5`(빠르고 쌈), `BRC_AI_MODEL`로 바꿀 수 있음(형식 검사).
- 키: 플러그인이 저장한 키(헤더 `X-BRC-AI-Key`, 루프백 엔진에만) → 엔진 환경변수 `BRC_AI_KEY` → `ANTHROPIC_API_KEY`.
- 실패 이유를 한국어로: 키 거부(401/403)·한도(429)·서비스 오류(5xx)·인터넷 없음·시간 초과(20초)·형식 오류 → 화면 출처 줄에 그대로.
- 회사 프록시는 `HTTPS_PROXY`를 따른다. 10-30 클라우드에서 잘못된 키로 실제 호출 → '키를 받지 않았습니다'(401) 확인. **실제 키로 받은 설명은 사용자 PC에서 확인할 것(확인표 67~72).**

## 7. 한계 (발표에서 말하지 않을 것)

- AI 문장은 **설명일 뿐**이다. 판정·수치·제안은 엔진이 정하고 AI가 바꿀 수 없다 — “AI가 규정을 판단한다”고 말하지 않는다.
- 숫자를 한글로 풀어 쓴 값(“오백”)은 단위 단어가 없으면 검사가 못 잡을 수 있다(지시문으로 막고, 숫자는 빈칸으로만 채움).
- 판정 상태가 '수정 소요'라는 사실, 원인 객체 종류, 고칠 방향은 밖으로 나간다 — 숫자·이름이 없어도 “어떤 배에 가시거리 문제가 있다” 정도는 알 수 있다. 이것까지 막아야 하는 도면이면 AI 설명을 끈다(기본값).
- 인터넷·키가 없는 본선장에서는 기본 설명으로 시연한다(같은 창, 출처 줄만 다름).

## 8. 시연 대본(20초)

1. 컨테이너 추가 → 가시거리 카드 '수정 소요' → **[설명]** → 기본 설명이 바로 뜨고 1~3초 뒤 AI 설명으로 바뀜(출처 줄 “AI 설명 · claude-haiku-5-5”).
2. **[보낸 내용]** → “숫자·이름 없이 조항·판정·빈칸만 보냈다”를 화면으로.
3. 버전 비교 → [생산팀 전달] → [AI 초안] → A4에 변경 설명.
