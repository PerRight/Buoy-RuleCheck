# 생성형 AI 설명 (2026-10-30 결정)

> 엔진 0.6.0 · 플러그인 0.7.0. 코드: `engine/brc/explain.py`(엔진 문장·보낼 사실·AI 문단 검사), `engine/brc/ai.py`(외부 호출 한 곳),
> `autocad/BuoyRuleCheck/AiExplain.cs`(설명 창·변경 설명 창·BRCAI). 테스트 `engine/tests/test_explain.py`.
> 검증: [docs/review/2026-10-30_AI설명_검증기록.md](review/2026-10-30_AI설명_검증기록.md)(Sonnet 1~3차).

## 1. 결정

| 항목 | 정한 것 |
|---|---|
| 방식 | **A — 외부 LLM(Claude API)에 숫자·이름을 보내지 않는다.** 숫자가 든 판정 문장은 PC 안의 엔진이 쓴다. (B 로컬 LLM은 시연 PC 설치·속도·한국어 품질 위험, C 템플릿만은 AX 해커톤에서 AI 요소가 없음) |
| 범위 | 항목 카드 **[설명]**(판정 설명) + 생산팀 전달 A4의 **변경 설명** |
| 기본값 | **꺼짐.** `BRCAI`에서 켜고 API 키를 넣어야 보낸다. 꺼져 있거나 키·인터넷이 없으면 엔진 문장만 |
| 원칙 | "도면 내용을 외부 서비스로 보내지 않는다"는 그대로 — 정해진 어휘만 보낸다. 외부로 나가는 코드는 `ai.py` 하나 |
| 누가 | 사용자(팀) 결정 10-30, 구현 Claude(Opus), 검증 Sonnet |

**10-30 구조 조정(2차 검증 뒤)**: 처음에는 AI가 판정 문장 전체를 `{사각거리}` 같은 빈칸으로 다시 쓰고 PC에서 채웠다. 2차 검증에서 이 방식은 문장 검사로 반대 판정을 막기 어렵고('수면'의 '면' 한 글자로 반대 판정 검사가 풀림, '문제가 없습니다' 같은 동의어 통과), 정상 문장도 많이 버린다(시연 장면 통과 47%)는 것이 드러났다. 그래서 **판정·숫자 문장은 언제나 엔진이 쓰고, AI는 그 뒤에 숫자·판정 표현 없는 설명 문단만 덧붙이게** 바꿨다. 결정 A의 목표(숫자·이름을 보내지 않음, 숫자는 PC 안 엔진 값)는 그대로이고 더 엄격해졌다(빈칸 이름도 보내지 않음).

## 2. 무엇을 보내고 무엇을 안 보내나

| 보낸다 (이 저장소에 적힌 정해진 어휘) | 보내지 않는다 |
|---|---|
| 규칙 ID·이름·조항(`SOLAS Ch.V Reg.22.1.1` 등) | **숫자 전부** — 좌표·치수·LOA·L·흘수·거리·건수 |
| 판정 상태 코드(`fail`/`pass`/`na`/`review`/`skip`) | 흘수 조건 이름(예: '밸러스트 도착') |
| 판정 분류의 뜻(“사각 거리를 줄여야 하는 경우” — 판정·비교 표현 없이) | 객체 번호(handle)·레이어·블록 이름 |
| 원인 객체의 **역할 종류**(장애물·선체 윤곽), 다른 객체도 가리는지·등흘수만 있는지(참/거짓) | 도면·파일·선명·버전 이름 |
| 고칠 방향(“격벽을 선미 쪽으로 옮기기” — 양 없이), 규칙이 다루지 않는 범위 | 엔진 판정 문장·제안 문장, 빈칸 이름 |
| 변경 설명: 바뀐 항목 **종류**(장애물 추가·충돌격벽 수정 …, 고정 순서), 설계팀 확인이 필요한 **규칙 이름**, 다른 변경의 영향 여부 | 수정 소요가 늘었는지·줄었는지, 해결 여부, 판정 결과 |
| — | API 키(헤더로만, 본문·미리보기에 없음) |

[보낸 내용](설명 창) · [보낼 내용 미리보기](BRCAI)가 실제 본문 전체를 그대로 보여 준다(CLI: `python -m brc explain <도면> --mode preview`).

## 3. 흐름

```
엔진 판정(RuleResult) ─ explain.rule_brief ─┬─ 엔진 문장 template + 빈칸 값(evidence.display) ─ fill ─▶ "수정 소요: … 433.84 m … 280 m …"  (PC 안)
버전 비교(/v1/compare) ─ explain.change_brief ┤
                                             └─ 보낼 사실 public ──(mode=ai, 키 있음)──▶ ai.call ─▶ Claude API
                                                                                                │
             표시 = 엔진 문장 + " " + AI 문단  ◀── check_ai_text 통과 ◀── AI 문단(숫자·판정 표현 없음)
                    └ 통과 못 하면 AI 문단을 버리고 엔진 문장만 + 이유(fallback_ko)
```

- 숫자는 **엔진이 판정 문장에 쓴 표시 문자열 그대로**다(`evidence.display` — 사각 거리·한도·제안 위치·제안 높이·격벽 거리·허용 범위·여유). 반올림을 두 번 하지 않으므로 카드·명령줄·리포트의 숫자와 같다(1차 검증 V1, 소수 넷째 자리 좌표 퍼징으로 고정). 표시 문자열이 없는 결과는 엔진 판정 문장을 그대로 쓴다.
- AI 문단에는 숫자도 판정도 없다 — 규칙이 왜 있는지, 이 판정이 다루지 않는 범위, 검토할 방향(변경 설명은 생산팀이 확인·반영할 것).
- 응답: `text`(엔진 문장 + AI 문단), `template_text`(엔진 문장), `ai_text`(AI 문단 또는 null).

## 4. AI 문단 검사 (`check_ai_text`) — 하나라도 걸리면 AI 문단을 버린다

1. 길이 10~450자, 문장이 끝나야 함(‘.’·‘다’·‘요’ 등, 닫는 따옴표·괄호는 허용). 응답의 `stop_reason`이 `end_turn`·`stop_sequence`가 아니면(잘림·거절) 버림
2. 보이지 않는 글자·제어 문자(서식·결합 문자, 한글 채움 문자, 변이 선택자, 줄 구분), 한글 음절·ASCII·기본 문장 부호가 아닌 글자, 중괄호(전각 포함)
3. 조항 문자열을 지운 뒤(앞뒤에 숫자·영문이 붙거나 점 뒤에 글자가 이어지면 지우지 않음 — `Reg.22.1.15`·`22.1.1m` 밀수 차단, 문장 끝 마침표는 허용) 숫자 문자(유니코드 숫자 분류 전부, 정규화 전후), 이모지·기호(🔟 등), 한자
4. 숫자를 글로 쓴 값(낱말 첫머리에서만 — '나열한'·'파라미터'·'선박이 천천히'는 숫자가 아님): 한글 수사(이십·오백·삼십삼·십오·백만), 고유어 수사(다섯 이상·열두·스물·서른 …), '영 점 오'·'이분의 일' 꼴, 절반, 단위(미터·센티·센치·밀리미터·킬로·피트·%·° …)
5. 영문 낱말(조항 표기·LOA·FP 같은 몇 개 말고) — 영어로 쓴 숫자·승인 표현 차단
6. 링크·마크업(`://`, `www.`, 꺾쇠·대괄호·`#`·`*`·백틱·`|`·밑줄)
7. 판정·비교 표현(NFKC·소문자): 문제없·문제가 있·이상 없·수정 소요·확인 필요·적용 제외·위반·충족·만족·미달·초과·넘다(넘습·넘어·넘지 …)·기준 안·이내·범위 안·한계 안·벗어·정상·양호·준수·부합·해결·줄었·늘었·증가·감소·괜찮·'보다 길/짧/높/낮 …', 적합·승인·합격·인증·보증·통과·확정·안전·인정·허가(한자 포함). 띄어쓰기를 끼운 우회('적 합', '문제 없 습니다')도 잡되, 띄어쓰기가 낀 일치는 낱말 첫머리에서 시작할 때만('다시 검사해 결과'의 '해 결'은 우연)

판정 표현을 상태와 상관없이 막으므로 반대 판정이 나올 길을 크게 줄이지만, **낱말 목록이라 완전하지는 않다**(3차 검증에서 '고칠 필요가 없습니다'·'지장이 없습니다'·'규정에 맞습니다' 같은 새 동의어가 나와 목록에 더했다 — 앞으로도 새 표현은 나올 수 있다). 그래서 판정·숫자는 언제나 AI 문단 위의 엔진 문장에 따로 있고, 화면도 'AI 문단의 숫자·판정 표현은 엔진이 걸러 냄'이라고만 말한다. 판정이 '문제없음'일 때는 '수정해야·고쳐야·옮겨야' 같은 처방도 막는다(수정 소요·확인 필요 설명에서는 자연스러운 처방이라 허용). 머리말('다음은…')·사과('죄송…')도 막는다. 그 밖에: 쓸 수 있는 글자는 한글 음절·ASCII·기본 문장 부호뿐(자모 분리·키릴·가나 등 차단), 제어 문자 거부, 한글 사이에 끼운 한글 아닌 한두 글자(문장 부호·밑줄·영문)를 지우고 검사('문-제-없-음', '문V제V없V음'), 문장이 끝나지 않은 답(잘린 답)과 `stop_reason: max_tokens`는 버린다. 2음절 일반 낱말(이내·넘어·정상 등)은 띄어쓰기를 낀 우연 일치('이 내용')를 보지 않고, '범위 안'·'인정'·'허가'·'위험'·'부족'은 서술형('…안입니다', '인정됩니다', '위험합니다')만 막는다. 그럴듯한 AI 문단이 통과하는지는 `Guard.test_realistic_paragraphs_pass`·`Round3.test_x2_natural_words_not_blocked`로 함께 본다.

## 5. 외부 호출 (`ai.py`)

- 주소 고정 `https://api.anthropic.com/v1/messages`, 리다이렉트 거부, `anthropic-version: 2026-10-21`(10-30 문서 확인 — 이 버전부터 temperature 등은 보내지 않음).
- 모델 기본 `claude-haiku-5-5`(빠르고 쌈), `BRC_AI_MODEL`로 바꿀 수 있음(형식 검사).
- 키: 플러그인이 저장한 키(헤더 `X-BRC-AI-Key`, 루프백 엔진에만) → 엔진 환경변수 `BRC_AI_KEY` → `ANTHROPIC_API_KEY`. 플러그인이 넘긴 키의 모양이 틀리면 환경변수 키로 넘어가지 않는다.
- 실패 이유를 한국어로: 키 거부(401/403)·한도(429)·서비스 오류(5xx)·인터넷 없음·시간 초과·HTTP가 아닌 응답·형식 오류 → 화면 출처 줄에 그대로. 그 밖의 어떤 예외도 엔진 문장만으로(서버 500 없음).
- 시간 제한 20초: 요청 전체를 별도 스레드에서 돌리고 20초(+1초)가 지나면 기다리지 않는다(연결·응답 머리·본문 모두). 플러그인은 기본 설명 10초·변경 설명 30초·AI 45~60초에서 끊고, 시간 초과를 '엔진 꺼짐'으로 보지 않는다.
- 회사 프록시는 `HTTPS_PROXY`를 따른다. 10-30 클라우드에서 잘못된 키로 실제 호출 → '키를 받지 않았습니다'(401). **이것은 주소·인증 단계까지만 확인한 것**이다(`anthropic-version`·모델 이름이 맞는지는 모른다). 틀리면 400/404 → 엔진 문장만으로 안전하게 돌아가지만 AI 문단은 나오지 않으므로, **시연 전에 실제 키로 확인표 69~70을 꼭 한 번** 해 볼 것.

## 7. 한계 (발표에서 말하지 않을 것)

- AI 문단은 **덧붙이는 설명일 뿐**이다. 판정·수치·제안은 엔진이 정하고 AI는 그 문장을 바꿀 수 없다 — “AI가 규정을 판단한다”고 말하지 않는다.
- 검사는 낱말 목록·패턴이라 모든 표현을 막지는 못한다(예: 넷 이하 고유어 수사 '셋', 판정 표현의 새 동의어). 다만 숫자·판정은 엔진 문장이 앞에 따로 있고, 의심되면 AI 문단을 버린다.
- AI가 지시를 잘 따르는지(통과율)는 실제 키로만 잴 수 있다 — 시연 전 확인표 69~70.
- 판정 상태 코드, 원인 객체 종류, 고칠 방향은 밖으로 나간다 — 숫자·이름이 없어도 “어떤 배에 가시거리 문제가 있다” 정도는 알 수 있다. 이것까지 막아야 하는 도면이면 AI 설명을 끈다(기본값).
- 인터넷·키가 없는 본선장에서는 엔진 문장만으로 시연한다(같은 창, AI 문단과 출처 줄만 다름).

## 8. 시연 대본(20초)

1. 컨테이너 추가 → 가시거리 카드 '수정 소요' → **[설명]** → 엔진 문장이 바로 뜨고, 1~3초 뒤 아래에 AI 문단(이 규정이 왜 있는지·측면도만 봤다는 범위·검토 방향)이 붙음.
2. **[보낸 내용]** → “숫자·이름 없이 조항·판정 상태·방향만 보냈다”를 화면으로.
3. 버전 비교 → [생산팀 전달] → [AI 초안] → A4에 변경 설명.
