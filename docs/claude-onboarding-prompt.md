## 구조
- engine/garc (Python 표준 라이브러리만): contract(입력 계약) → rules(규칙 2개) → engine(판정·상태) → session(revision diff·캐시) → server(127.0.0.1:8765) / report(HTML)
- autocad/GaRuleCheck (C# .NET 10, AutoCAD 2027): 도면 스냅샷 추출 → 엔진 호출 → 팔레트·리본·도면 표시. 판단은 하지 않는 어댑터.
- samples/: 합성 GA DXF(S140 rev0~4). 실제 조선소 도면은 아직 없다.

## 절대 어기면 안 되는 원칙
- 판정은 엔진만 한다. C#에 판정·단위 변환·diff 로직을 넣지 않는다. LLM이 pass/fail을 정하게 만들지 않는다.
- 모르면 멈춘다: 입력 누락은 na, 조건 밖·모순·모호는 review. 하나라도 있으면 전체 incomplete(주황). 일부 통과를 초록으로 보이게 하지 않는다. 엔진 연결 실패도 검토 불가.
- 플러그인은 매번 GA_ 레이어 전체 스냅샷을 보낸다. 증분 갱신 금지. 캐시 키 = (규칙 ID, 그 규칙 입력의 해시) → Undo 시 이전 결과 재사용.
- 도면 위 표시는 Transient만. 위반 표시하려고 도면 객체의 색·레이어를 바꾸지 않는다.
- 수치 제안("얼마나 낮추면 통과")은 엔진이 계산한다.
- 선급 승인처럼 보이는 문구 금지("적합/승인/통과 확정"). "규칙 후보 기준 충족 — 최종 판단은 설계자 검토"를 쓰고, 면책 문구는 항상 화면에 둔다.
- 규칙을 추가하거나 바꾸면 engine/tests/cases/expected_24.json에 정상·경계·위반·누락 케이스를 같이 넣고, scripts/render_cases.py로 docs/test-cases.md를 다시 만든다. 기대값을 엔진 출력에 맞춰 고치지 말고, 손으로 계산한 근거(hand_calc)를 먼저 쓴다.

## 현재 상태 (2026-10-13 기준)
- 엔진: 테스트 통과 (24건 기대값 + 입력 계약·revision·서버·리포트·DXF + 오류 회귀 test_robustness.py).
- 플러그인: v0.3까지 AutoCAD 2027 실기 확인. v0.3.1(10-12 오류 수정)은 빌드 성공, v0.3.2(유사 레이어 신호 등)는 빌드 미확인, 실기 확인표 1~14 미실행. 리본·카드형 팔레트·선박 정보 탭·상태 표시줄 알림·객체 툴팁·라벨 확대(구 '발표 모드') 있음.
- 오류 수정·검증 기록: docs/review/2026-10-12_오류수정_검증기록.md
- 저장소: GitHub 공개(Public) 저장소로 공유. main은 항상 테스트 통과 상태 — 작업은 브랜치 → PR(체크리스트) → Actions 초록 → 병합. 실도면 DWG·DXF와 검토 리포트는 커밋하지 않는다.
- 미완: 24건 수기 검산(verified_by 비어 있음), SOLAS 판본 대조, 실제 GA 도면, 평면도 ±10° 검토 여부 미결정.

## 작업 방식
- 모델: 기본 작업은 Opus 5.5. 막히면 Fable 5.1(Agent `model: "fable"`) 사용 허가. 엔진·규칙·기대값·C#·입력 계약을 바꾸면 Sonnet 5.5(Agent `model: "sonnet"`) 서브에이전트로 독립 검증하고 결과를 docs/review/에 남긴다(CLAUDE.md §6 '모델 사용 규칙').
- C# 코드는 너의 환경에서 빌드가 안 될 수 있다. 빌드 확인을 못 했으면 "빌드 미확인"이라고 분명히 말하고, 사용자가 Windows에서 autocad\install.ps1을 돌려 오류를 붙여 주면 그걸로 고친다. AutoCAD API 이름이 모호하면(예: Polyline이 DatabaseServices와 GraphicsInterface 양쪽에 있음) 별칭으로 고정한다.
- 엔진을 바꾼 뒤에는 반드시 테스트를 돌리고 결과를 보고한다.
- 주석·문서·커밋 메시지는 한국어, 식별자는 영어. AutoCAD 2027 기준(.NET 10, 번들 SeriesMin R26.0).
- 조선소 실도면은 보안 자료일 수 있다. 도면 내용을 외부 서비스로 보내는 코드를 만들지 않는다(엔진은 127.0.0.1 전용).
- 규정 수치·조항을 기억으로 단정하지 말고, 근거가 불확실하면 rule-definitions.md에 "확인 필요"로 남긴다.
